# CE-Frontend 版本发布流程指南

## 📋 概述

本文档说明如何进行版本发布，包括小更新（热更新）和大版本发布（完整构建）。

---

## 🔄 两种更新方式

### 1️⃣ **小更新（热更新 - Patch）**

**适用场景：**
- ✅ Bug 修复
- ✅ 文案调整
- ✅ UI 微调
- ✅ 业务逻辑优化
- ❌ **不能修改原生代码**
- ❌ **不能添加新的第三方依赖**

**流程：**
```bash
# 1. 修改代码
# 2. 测试验证
# 3. 提交代码
git add .
git commit -m "fix: 修复登录按钮点击无响应"
git push

# 4. 本地推送热更新
# Android
shorebird patch android --release-version=1.0.1

# iOS
shorebird patch ios --release-version=1.0.1

# 如果需要传递 dart-define 参数
shorebird patch android --release-version=1.0.1 -- \
  --dart-define=API_URL=http://10.0.2.2:8080/api \
  --dart-define=XFYUN_APP_ID=your_app_id
```

**优点：**
- 用户无需重新安装
- 下次启动时自动更新
- 适合快速修复问题

---

### 2️⃣ **大版本发布（完整构建 - Release）**

**适用场景：**
- ✅ 新功能上线
- ✅ 添加新依赖（如新的插件）
- ✅ 修改原生代码（Android/iOS）
- ✅ 重大架构调整
- ✅ 版本号升级

**流程：**

#### Step 1: 修改版本号

编辑 `pubspec.yaml`：

```yaml
# 修改前
version: 1.0.1+1

# 修改后（小版本更新）
version: 1.0.2+2

# 或大版本更新
version: 1.1.0+3

# 或主版本更新（重大改动）
version: 2.0.0+4
```

**版本号规则：**
- `主版本.次版本.修订号+构建号`
- `1.0.2+2`
  - `1` - 主版本（重大架构变化）
  - `0` - 次版本（新功能）
  - `2` - 修订号（Bug 修复）
  - `2` - 构建号（每次构建递增）

#### Step 2: 提交代码

```bash
git add pubspec.yaml
git commit -m "chore: 升级版本到 1.0.2"
git push origin master
```

#### Step 3: 打 Git Tag

```bash
# 创建 Tag（版本号与 pubspec.yaml 一致）
git tag v1.0.2

# 推送 Tag 到远程仓库
git push origin v1.0.2
```

**⚠️ 重要：** Tag 的版本号**必须**与 `pubspec.yaml` 中的版本号一致，否则 CI 会失败！

#### Step 4: 等待 GitHub Actions 构建

推送 Tag 后：

1. 访问 GitHub 仓库的 **Actions** 标签页
2. 等待 **Release - Build & Deploy** 工作流完成（约 30-60 分钟）
3. 构建成功后会自动创建 GitHub Release

#### Step 5: 下载安装包

1. 访问 **Releases** 页面
2. 找到对应版本（如 `Chrono v1.0.2`）
3. 下载对应平台的安装包：
   - `chrono-android-v1.0.2.apk` - Android 普通版
   - `chrono-android-shorebird-v1.0.2.apk` - Android 热更新版
   - `chrono-ios-v1.0.2.ipa` - iOS 普通版
   - `chrono-ios-shorebird-v1.0.2.ipa` - iOS 热更新版

#### Step 6: 发布到应用商店（可选）

- **Google Play / 华为应用市场：** 使用普通版 APK
- **App Store：** 需要重新签名 IPA
- **内测分发：** 使用 Shorebird 版本（支持热更新）

## 🛠️ 手动推送热更新

### Shorebird Patch 命令使用

**前提条件：**

1. **已安装 Shorebird CLI**
   ```powershell
   # Windows (PowerShell)
   iwr -UseBasicParsing 'https://shorebird.dev/releases/stable/windows/shorebird-installer.ps1' | iex
   ```

2. **已登录 Shorebird**
   ```powershell
   shorebird login
   ```

3. **已推送过至少一个 Release 版本**
   - 必须先通过 Git Tag 触发 CI 构建
   - 构建成功后，Shorebird 后台才会有对应的 Release
   - Patch 是基于 Release 版本的增量更新

**基本用法：**

```bash
# 1. 查看可用的 Release 版本
shorebird releases list --platform android
shorebird releases list --platform ios

# 2. 推送 Android Patch（简单模式）
shorebird patch android --release-version=1.0.1

# 3. 推送 iOS Patch（简单模式）
shorebird patch ios --release-version=1.0.1

# 4. 推送 Patch 并传递 dart-define 参数（完整模式）
shorebird patch android --release-version=1.0.1 -- \
  --dart-define=API_URL=http://10.0.2.2:8080/api \
  --dart-define=XFYUN_APP_ID=your_app_id \
  --dart-define=XFYUN_ACCESS_KEY_ID=your_key_id \
  --dart-define=XFYUN_ACCESS_KEY_SECRET=your_secret
```

**注意事项：**

- ⚠️ `--release-version` 必须与目标 Release 版本号一致（从 pubspec.yaml 获取）
- ⚠️ Patch 不会修改版本号，用户看到的仍是原版本号
- ⚠️ 如果报错 "No release found"，说明还未推送过该版本的 Release
- ⚠️ 如果构建时使用了 `dart-define`，推送 Patch 时也需要传递相同的参数
- 💡 `--` 分隔符后面的参数会传递给 Flutter 构建命令

## ⚙️ CI/CD 工作流说明

### ci.yaml - 代码质量检查

**触发时机：**
- ✅ 提交 PR 到 master
- ✅ 推送到 master 分支

**执行内容：**
- ✅ 代码格式检查（`dart format`）
- ✅ 静态分析（`flutter analyze`）
- ✅ 单元测试（`flutter test`）
- ✅ 测试覆盖率上传（Codecov）
- ✅ Debug 模式编译验证

**不会：**
- ❌ 构建 Release 安装包
- ❌ 推送到 Shorebird
- ❌ 创建 GitHub Release

### release.yaml - 版本发布

**触发时机：**
- ✅ 推送 Git Tag（格式：`v*.*.*`）
- ✅ 手动触发（Actions → Release → Run workflow）

**执行内容：**
1. **版本验证** - 检查 Tag 与 pubspec.yaml 是否一致
2. **构建 Android 普通版** - 适合应用商店
3. **构建 Android Shorebird 版** - 支持热更新
4. **构建 iOS 普通版** - 未签名 IPA
5. **构建 iOS Shorebird 版** - 支持热更新
6. **创建 GitHub Release** - 自动上传所有安装包
7. **生成 Changelog** - 自动从 Git 提交记录生成

### 场景：修复登录 Bug

```bash
# 1. 修改代码并测试
```

## �📊 版本号管理策略

### 语义化版本（SemVer）

格式：`主版本.次版本.修订号+构建号`

| 版本类型 | 何时递增                     | 示例变化         |
| -------- | ---------------------------- | ---------------- |
| 主版本   | 重大架构变化、不兼容更新     | `1.0.0` → `2.0.0` |
| 次版本   | 新增功能、向下兼容           | `1.0.0` → `1.1.0` |
| 修订号   | Bug 修复、小改动             | `1.0.0` → `1.0.1` |
| 构建号   | 每次构建递增（CI 自动管理）  | `1.0.0+1` → `1.0.0+2` |

### 实际案例

```yaml
# 场景 1: 修复紧急 Bug
version: 1.0.1+1 → 1.0.2+2

# 场景 2: 新增日历功能
version: 1.0.2+2 → 1.1.0+3

# 场景 3: 全新重构（不兼容旧版）
version: 1.1.0+3 → 2.0.0+4
```

## 🔍 常见问题

### Q1: 如何回滚 Patch？

**方法：** 推送一个新的 Patch 覆盖旧版本

```bash
# 1. 恢复代码到正确版本
git revert <commit_hash>

# 2. 推送新的 Patch
shorebird patch android --release-version=1.0.1
```

### Q2: 版本号写错了怎么办？

**情况 A：还未推送 Tag**
```bash
# 修改 pubspec.yaml 后重新提交
git add pubspec.yaml
git commit --amend
git push --force
```

**情况 B：已经推送了 Tag**
```bash
# 1. 删除本地 Tag
git tag -d v1.0.2

# 2. 删除远程 Tag
git push origin :refs/tags/v1.0.2

# 3. 修改 pubspec.yaml 后重新打 Tag
git add pubspec.yaml
git commit -m "chore: 修正版本号"
git push
git tag v1.0.2
git push origin v1.0.2
```

### Q3: CI 构建失败怎么办？

**检查步骤：**

1. **版本号不匹配**
   ```
   错误：❌ 错误：版本号不匹配！
   解决：确保 Tag 与 pubspec.yaml 一致
   ```

2. **Secrets 未配置**
   ```
   错误：Error: API_URL is not defined
   解决：在 GitHub 仓库设置 → Secrets 中添加
   ```

3. **Shorebird Token 过期**
   ```
   错误：Authentication failed
   解决：重新生成 Token 并更新 Secret
   ```

### Q4: 如何查看 Patch 历史？

```bash
# 查看所有 Patch
shorebird patches list

# 查看所有 Release
shorebird releases list --platform android
shorebird releases list --platform ios

# 查看特定 Release 的 Patch
shorebird patches list --release-version=1.0.1
```

### Q5: Patch 对哪些用户生效？

- ✅ 安装了对应 Release 版本的 **Shorebird 版本**用户
- ❌ 普通版用户（不支持热更新）
- ❌ 更旧或更新版本的用户

**示例：**
```
Release v1.0.2 → Patch #1 → 只有 v1.0.2 Shorebird 用户会收到
Release v1.0.3 → 不受影响
```
